# Исследование PowerPoint через REA + Ghidra

**Обновление, 18 октября 2026 года:** завершены отдельные проходы PPCORE, OART и MSO. Прежний таймаут PPCORE преодолён: стандартный автоанализ Ghidra определил 72 795 процедур и 5 477 строк. Новые исследования связывают типы команд PPCORE с конструкторами OART и восстанавливают общую таблицу идентификаторов MSO. Это целевое исследование отдельных маршрутов, а не полная декомпиляция PowerPoint. Ниже сохранён первоначальный журнал и его ограничения на тот момент.

Результаты относятся к установленному Windows Office12; они не описывают современный Microsoft 365 или нативный движок macOS. Исходники, псевдокод, бинарные ресурсы и изображения Microsoft в продукт не переносились.

## Первоначальный журнал исследования

Дата: 18 октября 2026 года. Исследован установленный в системе PowerPoint из Office12. Это старая Windows-версия; результаты не описывают современный PowerPoint Microsoft 365 и его macOS-реализацию.

## Объект и инструменты

- Файл: `C:\Program Files (x86)\Microsoft Office\Office12\POWERPNT.EXE`.
- SHA-256: `cd02e31976924214d0c9aec1588e85bd00003547fb95af678a8f1516bf6a3773`.
- Формат: нативный PE x86; REA 6.5.0; Ghidra 12.1.4; Temurin JDK 21.0.12.1, 64 bit.
- Только статический анализ: исходный EXE не изменялся и PowerPoint для этого исследования не запускался. Ghidra импортировала файл во временную базу с автоматическим анализом.

## Исправление запуска анализа

Первоначальный MCP-запуск Ghidra завершался до появления bridge с ошибкой пути. В терминальной песочнице независимая проверка `child_process.spawnSync(java.exe)` возвращала `EPERM`, хотя непосредственный запуск Java из PowerShell работал. Это два разных ограничения.

Успешный путь: публичный CLI `rea.mjs`, разрешённый запуск дочерних процессов, только переменные окружения текущего процесса и ASCII-эквиваленты 8.3 для `GHIDRA_INSTALL_DIR`, `JAVA_HOME`, `USERPROFILE`, `TEMP`, `TMP`. Постоянная конфигурация REA, Codex, Java и Ghidra не изменялась. Не утверждается, что установлена единственная первопричина первоначальной ошибки: успешный запуск изменил и пути, и контекст разрешений.

Использованные команды CLI после настройки окружения:

```text
rea analyze "C:/Program Files (x86)/Microsoft Office/Office12/POWERPNT.EXE" --provider ghidra --format json
rea search "C:/Program Files (x86)/Microsoft Office/Office12/POWERPNT.EXE" "PPCORE|LoadLibrary|Ppt|Office" --mode regex --kind strings --provider ghidra --format json
rea search "C:/Program Files (x86)/Microsoft Office/Office12/POWERPNT.EXE" "WinMain|LoadLibrary|GetProc|entry" --mode regex --kind procedures --provider ghidra --format json
rea function "C:/Program Files (x86)/Microsoft Office/Office12/POWERPNT.EXE" 0x300010c4 --provider ghidra --format json
```

Файлы `ghidra-overview.json` и `ghidra-overview-unicode-java.json` сохраняют неудачные диагностики до разрешённого запуска; это не успешные результаты исследования.

## Связь с AI Presentation Free и границы

AI Presentation Free реализована самостоятельно: модель слайдов и объектов, редактор на веб-технологиях, отдельная настольная оболочка Electron, обмен файлами через собственную реализацию и библиотеки. Выбор этой архитектуры — инженерное решение для Windows и macOS, а не восстановленная архитектура PowerPoint.

Бинарный анализ выше подтверждает только перечисленные факты загрузчика. Он **не** подтверждает полноту формата PPTX, работу рендерера, алгоритмы совместного редактирования, анимации, совместимость с современным Office или устройство версии для Mac. Логотип и интерфейс AI Presentation Free созданы независимо. Бинарные компоненты, изображения и код Microsoft в приложение не включены.

Ghidra определяет лишь распознанные строки и процедуры; нераспознанные данные могут отсутствовать в инвентаре. Состояние загрузки PDB неизвестно. Имена `FUN_*`, типы и псевдокод — результат анализа, не оригинальные исходники. Статический граф вызовов не является записью выполнения. Полные ограничения сохранены внутри каждого Evidence JSON.

## Продолжение: движок PPCORE и русские ресурсы интерфейса

После запроса на привычное расположение команд область исследования расширена на точный файл `Office12/PPCORE.DLL` и локализованный `Office12/1049/PPINTL.DLL` той же установки.

Обычного MENU (4) нет. | `research/ppintl-ru-pe-resources.json`, `ev_68921c36bb401eac8c8ffbb2778424409081d2a578664991fcc86616be73418b` |

Отдельный **аналитический скрипт, не вывод движка REA**, `research/extract-ui-identifiers.py`, проверяет SHA-256 исходного файла и каждого выбранного payload, затем ищет ASCII-идентификаторы и фрагменты UTF-16LE строго внутри ресурсных диапазонов, допущенных REA. Результат `research/ppintl-ui-identifiers.json`: 801 совпадение в 106 ресурсах. Это не парсер закрытого формата UIFILE: соседние строки могут склеиваться, а совпадения — содержать только часть подписи.

В наблюдаемых байтах есть подписи и идентификаторы, относящиеся к созданию слайда, вставке, формату, сортировщику, образцу слайдов, шрифту и цвету шрифта, смене слайдов, анимации текста, действиям при щелчке, колонтитулам, печати скрытых слайдов, автосохранению и библиотеке слайдов. Среди буквальных идентификаторов — `SaveAutoRecover`, `SaveWithFonts`, `PrintHiddenSlides`, `FrameSlides`, `SlideshowScale`, `Paragraph`.

Эти данные помогают составить группы знакомых действий редактора. Они **не устанавливают порядок вкладок, положение кнопок на ленте, контекстную видимость, координаты элементов, горячие клавиши для каждого действия или полное поведение обработчиков**. Названия управляющих групп и относительное расположение ленты в AI Presentation Free — самостоятельная реализация для облегчения перехода. Полное совпадение всех функций PowerPoint по этому исследованию не доказано и не заявляется. Извлечённые изображения, курсоры, полные определения UIFILE и код Microsoft в продукт не перенесены.

### Незавершённый глубокий запрос PPCORE

Фокусированный запрос Ghidra к строкам PPCORE (`Ribbon|TabHome|TabInsert|SlideShow|NewSlide|DuplicateSlide|Slides|Clipboard|Paragraph|Animation`) завершился ошибкой REA `provider_timeout`, `timeout_ms=330000`, `Ghidra startup deadline elapsed`. Диагностика сохранена в `research/ghidra-ppcore-ui-strings.json`; это **ошибка, а не Evidence успешного анализа строк**. Журнал также сообщает ошибку XML-конфигурации Log4j при каноническом пути с кириллицей. Влияние этой ошибки на срок запуска отдельно не установлено. Наблюдавшаяся загрузка CPU процесса Java не доказывает, что полный автоанализ завершился.

REA самостоятельно завершила принадлежащий запросу процесс после таймаута; повторного неограниченного запуска и остановки посторонних Java-процессов не производилось. Успешными остаются четыре запроса Ghidra к `POWERPNT.EXE` и независимые полные ресурсные каталоги REA для PPCORE/PPINTL. Внутренние обработчики команд PPCORE и полная функциональность редактора в этом проходе не восстановлены.
