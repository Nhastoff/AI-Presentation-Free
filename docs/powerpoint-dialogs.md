# Геометрия диалогов PowerPoint 2007: статическое декодирование

Источник: установленный `Office12/1049/PPINTL.DLL` (русский интерфейс). Это дополнительный ограниченный парсер PE-ресурсов, а не результат декомпиляции Ghidra и не самостоятельная запись Evidence REA. Приложение не запускалось.

SHA-256 всего файла: `afd6af5fed336ede9a707d4b077b8440733ad8a7570ffad378e43cca8996b511`. Идентичность всего файла и каждого извлечённого payload проверена по сохранённой инвентаризации REA `ev_68921c36bb401eac8c8ffbb2778424409081d2a578664991fcc86616be73418b`.

Полностью разобраны **111 из 111** ресурсов RT_DIALOG: **1 467 элементов**, все в формате DLGTEMPLATEEX, **0 ошибок**, **0 неразобранных хвостовых байтов**. Число элементов каждого шаблона совпадает с объявленным количеством.

JSON сохраняет ID ресурса и языка, диапазон файла, SHA-256, заголовок, шрифт, стили, классы, ID, подписи, helpID, данные создания и x/y/cx/cy каждого элемента. Индекс элемента — порядок в шаблоне, а не проверенный порядок перехода Tab. `&` и ведущий `+` сохранены буквально из ресурса.

**Все координаты — dialog units, не пиксели.** Геометрия относится к клиентской области диалога; соответствие экранному размеру зависит от шрифта и DPI. Это не координаты кнопок ленты. Динамические элементы, изменения после создания, OS common dialogs и ресурсы других DLL этим парсером не покрываются.

Общий диалог шрифта, полный Save As и шаблон с заголовком «Переход» в этой выборке не найдены. Для шрифтов извлечены, например, встраивание и замена; для сохранения — предупреждение о невстраиваемых шрифтах. Для эффектов извлечены страницы «Время» и «Эффект». Это не доказывает отсутствие иных функций в PowerPoint.

## Воспроизведение и формат

Из корня проекта: `python research/ppcore-complete/extract-dialogs.py`, затем `python research/ppcore-complete/report-dialogs.py`. Требуется тот же исходный DLL; запись в Office не производится. Полные результаты: `research/ppcore-complete/dialogs.json`.

Парсер использует проверяемые границы каждого payload, UTF-16LE, DWORD-выравнивание элементов, стандартный DLGTEMPLATE и расширенный DLGTEMPLATEEX. Ненулевые данные создания сохраняются в hex. Любая ошибка диапазона, хеша или декодирования записывается как error; не интерпретируется эвристически.

Правила полей и единиц взяты из первичной документации Microsoft: [DLGTEMPLATE](https://learn.microsoft.com/en-us/windows/win32/api/winuser/ns-winuser-dlgtemplate), [DLGITEMTEMPLATE](https://learn.microsoft.com/en-us/windows/win32/api/winuser/ns-winuser-dlgitemtemplate), [DLGTEMPLATEEX](https://learn.microsoft.com/en-us/windows/win32/dlgbox/dlgtemplateex), [DLGITEMTEMPLATEEX](https://learn.microsoft.com/en-us/windows/win32/dlgbox/dlgitemtemplateex).
